# PR-2. Достоверность AI и безопасность: отчёт

## Источники знаний AI (найдено)
| Источник | Где | Кто читает | Утверждён Милой |
|---|---|---|---|
| Версионная база `knowledge_articles` / `knowledge_versions` (D1) | кабинет «ИИ», seed | заготовленные ответы AI, FAQ на главной | да, через кнопку утверждения (в демо стоит метка «DEMO placeholder») |
| Статичный `src/lib/ai-knowledge.ts` (SKILL_KNOWLEDGE) | код | системный запрос языковой модели | нет, в самом файле указано «НЕ подтверждены Милой» |
| Статьи библиотеки `library-articles.ts` | код | карточки сайта, ссылки AI, краткое содержание для модели | у каждой свой статус «на утверждении» / «утверждено» |

Конфликт: модель отвечала по статичному файлу, а утверждённая база в её запрос не попадала.

## Сделано в этом PR (без миграций и без деплоя)
1. В запрос модели добавлен отдельный блок «Утверждённые знания» (активная версия из базы, на языке клиента) с приоритетом над справочными сведениями. Статичный файл помечен как «НЕ утверждены Милой», добавлено правило не выдавать его как рекомендации Милы. Медицинские ограничения и передача человеку не менялись.
2. Адрес клиента для лимитов берётся из `cf-connecting-ip` (его ставит Cloudflare). Подделываемому `x-forwarded-for` в production больше не доверяем: без Cloudflare-заголовка запросы попадают в один общий строгий лимит.
3. Тесты `tests/pr2.test.ts` (5 проверок).

| Единый источник истины | Решение: источник = база в кабинете, статичный файл остаётся только как «справочный» до утверждения. Перенос фактов из файла в базу как черновики требует миграции данных и вашего «да» |

# PR-3 (первый срез): понимание времени в диалоге
Сделано: `src/lib/timeprefs.ts` разбирает пожелания RU/EN/UA («завтра утром», «в пятницу после 16:00», «на следующей неделе», «до 12») по местному времени Дублина, учитывая переход на зимнее время. Тесты: 7 новых юнит-тестов (62 в сумме), сквозная запись, чат на 3 языках и доступность чата без ошибок.
