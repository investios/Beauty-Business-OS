# AI-КОНСУЛЬТАНТ + МАРКЕТИНГОВЫЕ ВОРОНКИ

## Архитектура AI
**A / Expert knowledge** — точные сведения по утверждённым услугам, подготовке, длительности, ценам, базовым различиям, уходу, особенностям мастера.
**B / Consultative sales** — распознавание намерения, информирование, снятие неопределённости, объяснение ценности и переход к booking, без давления и ложных гарантий.
**C / Actions** — availability, create/modify/cancel appointment, waitlist, handoff, follow-up. Языковая модель только предлагает/запрашивает действие, которое выполняет безопасный server API.

### Логика разговора
1. Определить язык EN/RU/UA и сохранить предпочтение.
2. Определить канал + рекламный контекст, если доступен (не разглашать поведенческие данные и не делать вид, что знаешь больше разрешённого).
3. Выяснить намерение: уже записаться; спросить цену; сравнить методы; уточнить подготовку; сомнения; жалоба; перенос; сложное состояние.
4. **Сначала ответить на заданный вопрос**, при недостатке данных сказать, что точной информации пока нет; только затем спросить ОДНО релевантное уточнение.
5. Предложить конкретное полезное действие: информация / консультация мастера / свободные слоты / человеческий контакт.
6. При записи вызвать `getAvailability`, показать реальное время, спросить согласие, вызвать `createBooking`, дождаться `confirmed`, только тогда отправить финальное подтверждение.
7. Если консультация вне знаний мастера/медицинская/конфликтная — не выдумывать, создать handoff с кратким резюме и просьбой подтвердить человеком.

### Стиль по умолчанию
Короткие, тёплые, компетентные реплики. Без псевдодружбы, давления, повторяющихся «У вас замечательные волосы» без доказательства. Без манипулятивных скидок, не генерировать подробный медицинский диагноз. Стиль бренда (premium/warm/clinical) — конфигурация отдельно от базы фактов.

## Примеры разговоров — сценарные, НЕ настоящая модель
**RU, «цена»:** Клиент: «Сколько стоит?» → AI: «Стоимость зависит от выбранной процедуры и объёма работы. Могу показать утверждённые мастером варианты либо предложить консультацию для оценки. Вас интересует длина, густота или другая задача?» → клиент «густота» → AI: «Тогда подберём консультационный слот. Вот реальные свободные часы ...».
**EN:** Client: “Can I book a consultation?” → AI: “Yes. You can choose a free time in the calendar. Would Tuesday at 11:00 or Wednesday at 15:00 suit you?” (только из API, пример текстовый).
**UA:** Клієнт: «Чи можна перенести запис?» → AI: «Так, допоможу перевірити доступний час. Будь ласка, відкрийте ваше посилання керування записом або підтвердьте бронювання». Не раскрывать чужую запись по одному имени.
**Complex:** «Сильная реакция кожи, что делать?» → «Я AI-помощник, не могу оценить симптомы. Передам вопрос специалисту; если требуется срочная медицинская помощь, обратитесь к соответствующему медицинскому специалисту». Не выдавать unapproved советы.

## Front offers и рекламная система
Не рекламировать одинаково всё сразу. Каталог входных предложений:
- **Find your option:** мини-подбор услуги; цель — контекст консультации, не мгновенная продажа.
- **Mini guide:** полезный гайд о подготовке/уходе, подтверждённый мастером, с возможностью задать вопрос.
- **15-minute consultation:** отдельный слот консультации только если мастер подтвердил наличие/условия.
- **Show available times:** для горячего спроса сразу booking; не заставлять проходить опрос.
- **Case explainers:** рекламный кейс (с согласием) → объяснение метода → consult / book.

## Instagram / Facebook: trigger logic
1. `message.received` от пользователя → допустимый AI-диалог в разрешённое окно (проверять channel policies и user consents).
2. `comment.eligible` под поддерживаемым media/ad → публичный ответ или допустимый private reply; **не считать, что можно вести бесконечную личную переписку**, пока клиент не ответил и правила это не разрешают.
3. `ad.click` → deep-link landing/DM flow; не отправлять DM лишь за клик.
4. `like` → analytics, **НЕ автоматическая личка**.
5. `website.book_clicked` → быстрый booking; AI не требуется.
6. `website.ask_ai_clicked` → добровольный чат с контекстом услуги/источника.

### Пример кампании
Рекламный пост: «Хотите разобраться, какие варианты работы с густотой волос существуют? Получите краткую консультацию». Поддерживаемый комментарий → разрешённое приглашение в личку → пользователь сам отвечает → AI узнаёт фронт-продукт и спрашивает один вопрос → предлагает предварительную консультацию/реальное время → booking → transaction confirmation → CRM lead tag → разрешённый follow-up. Не делать этого для каждого лайка.

## Минимальные маркетинговые автоматизации
1. **Rebook**: после `appointment.completed` + сервисный период, правила мастера + разрешённый канал → ссылка на повторный визит.
2. **Referral**: уникальный share-link, reward только после состоявшегося первого визита реферала.
3. **Waitlist**: освободился слот → подходящая очередь → один короткий hold → дедупликация.
4. **Reactivation**: после превышения типового периода визита → персональное приглашение, если законно и разрешено.
Уведомления нейтрального запроса отзыва всем подходящим клиентам, но никаких подарков/баллов за Google review.

## Динамика по загрузке
<65% заполнения: сначала возврат, партнёрские контакты, кампании для новых.
65–85%: качество конверсии, удобство, повторные визиты.
>85%: защита расписания, buffer/time optimization, стоимость доступного часа, подготовка расширения.
**Пороговые проценты выше — пример конфигурации, не исследовательский факт и не готовая рекомендация каждому салону.**

## Протокол обучения AI
Взять 30–50 типовых обезличенных вопросов → мастер голосом/текстом даёт ответы → структурирование → master approval → тесты (правильный вопрос, неизвестная цена, медицинский/спорный случай, запись, перенос) → публикация версии → мониторинг ошибок → новые предложения карточек, строго после подтверждения мастера.

Не подменять «диалог состоялся» реальным клиентом.
