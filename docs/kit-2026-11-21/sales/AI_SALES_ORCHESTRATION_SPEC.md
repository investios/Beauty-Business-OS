# AI_SALES_ORCHESTRATION_SPEC — как ассистент выбирает сценарий

**Статус реализации: каркас готов, к исходящим сообщениям и ответам ассистента НЕ подключён.** Подключение — отдельное решение владельца после утверждения текстов (OWNER_APPROVAL_REQUIRED).

## Поток решения (одно сообщение)
1. **Вход недоверенный.** Текст клиента и внешних страниц никогда не меняет правила (guardrails): просьбы «пообещай скидку» отклоняются (проверено: baseline B15).
2. **Идентификация.** Клиент известен только по защищённой ссылке записи (`client-context.ts`). Без неё история и бонусы не раскрываются.
3. **Классификация намерения** (`ai.ts classify`) → кандидат семейства SC (таблица соответствий ниже).
4. **Шлюз `canUse(familyId, clientId)`** (`src/lib/playbooks.ts`): разрешено, только если
   - мастер утвердил это семейство, и версия каталога не изменилась после утверждения;
   - у клиента нет открытой жалобы;
   - для рекламных семейств есть действующее согласие на предложения;
   - клиент не в списке «не писать» (проверяется при отправке в lifecycle);
   Каждое решение пишется в `message_decision` с причиной (аудит).
5. **Факты.** Плейсхолдеры [..] заполняются только значениями из утверждённого реестра; нет значения → ответ уходит мастеру (handoff), цифра не придумывается.
6. **Состояние беседы** (`conversation_state`): стадия, семейство, возражение, причина подавления, следующее действие.
7. **Исход** записывается, «нет ответа» ≠ «доволен».

## Стадии и переходы
`lead_new → qualifying → price → objection → booking → reminder → pre_visit → post_visit → (complaint → complaint_suppressed) | review | aftercare → rebook_eligible → reactivation | lost`.
Из любой стадии: «стоп/отписка» → `lost` с подавлением; жалоба → `complaint_suppressed` до решения мастера.

## Что нужно для подключения (не сделано)
1. Новые намерения в `classify()` (возражения, жалоба, отзыв, перезвонить, молчание).
2. Утверждённый реестр фактов (`approved_claim_registry`): цены, составы, условия — ждёт D01.
3. Утверждение текстов мастером (страница «Сценарии общения» есть).
4. Реальный канал отправки (D02/D03).
5. Эксперименты и измерение исхода — после реальных отправок.
